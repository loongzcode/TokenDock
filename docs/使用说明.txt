TokenDock 1.0.0

启动后只在任务栏显示实际可读取的数据。单击打开详情，右键可设置位置。
详情底部的刷新、历史趋势、连接设置已改为真实按钮，支持悬停、按下及键盘焦点反馈。
刷新时显示等待状态并避免重复请求；完成后显示已刷新，部分数据失败时显示部分失败，可再次重试。
详情可按 F5 刷新，Tab 切换按钮，Enter / 空格激活按钮。
设置窗口采用紧凑的账户、显示、提醒目录，以细线分组，选项使用复选框，底部固定保存操作。
窗口去除大标题、卡片与装饰性说明，按钮和输入使用中性配色，保留焦点和按下反馈。
设置页面内容较多时可滚动；窗口会按当前屏幕可用区域缩小。
可直接拖动数据行，使用浮动预览与落点提示；Esc 或远离任务栏释放可取消。
鼠标停在某个项目上约半秒，会显示该项目的速览；离开、单击或拖动时关闭。
额度速览包含各周期剩余量、重置倒计时；设备速览包含连接状态、电量来源和更新时间。
右键“紧凑显示（图标 + 数值）”可缩短占用宽度；原有显示样式默认保留。
应用使用 Codex、Claude、DeepSeek 的 Logo；设备使用键盘、鼠标、耳机或通用蓝牙类型图标。
六点拖动提示只出现在拖动预览中，普通显示和悬停时都隐藏，也不占空位。
位置调整好后，右键勾选“锁定位置”可避免误拖动；也可在显示设置中切换。
锁定状态跨重启保留，仍可单击查看详情；取消锁定后恢复拖动。系统空间不足时仍会避让。
锁定只防止鼠标误拖动，设置中的“显示位置”和右键位置菜单仍可使用，手动切换不会关闭锁定。
右键“调整显示顺序…”可拖动项目或使用上移、下移；断开的设备保留顺序，新设备追加。
设置 → 显示 → 项目排序也可调整，点击设置页“保存”后生效。

新增设置
“账户”：Codex CLI 路径、Claude 状态栏配置、DeepSeek Key、刷新间隔、蓝牙读取和开机启动。
“显示”：选择常驻平台、选择 Codex / Claude 的额度或 Token 指标，勾选需要显示的设备。
也可切换常驻样式、关闭悬停速览。
“提醒”：分别开启额度、余额和低电量提醒，并设置阈值。
新增额度恢复提醒：对比先后两次成功读取，在周期已更新且剩余额度增加，或从低位恢复时通知。
首次启动、失败读取、过期数据，以及单独开启提醒开关都不会补发恢复通知。

历史趋势
从任务栏右键、托盘菜单或详情底部的“历史趋势”打开。
可选择额度、余额或设备电量，以及最近 24 小时、7 天、30 天。
数据从启用记录时开始积累，只记录实际读取结果，不补造过去的数据，也不推算 Token 消耗。
数值变化时记录；数值不变时最多每 5 分钟保留一次成功读取的采样。
图上的圆点为真实采样；超过 30 分钟未采样或额度周期更新时断线。
历史只保存在本机 %LOCALAPPDATA%\TokenDock\history，保留最近 30 个 UTC 日期的文件，写入时清理过期文件。
历史不保存 API Key、提示词、会话内容或账户原始响应。便携模式使用程序旁的 data\history。
可取消“记录本机历史”来暂停，已有历史仍可查看；重启后继续沿用设置。

多个已连接且有电量的设备会分别显示名称与百分比。设备未知或断开时自动隐藏。
新设备默认加入常驻显示；可在显示页单独取消。
已适配的 FLX1 2.4G 接收器使用厂商接口读取，并通过本机指纹绑定，不对其他同 VID/PID 鼠标盲目启用。
读取电量前后均检查鼠标状态；关机或查询失效时不显示接收器缓存的电量。
充电时显示“充电中”，不把设备在充电时上报的 100% 作为已充满；拔线后的百分比更新可能有延迟。
百分比来自厂商上报，不使用上次值、默认值或续航推算。该适配不代表蓝牙模式可读。
绑定使用本机哈希指纹和原蓝牙设备身份，切换连接方式时保留显示选择，避免重复出现两行。
程序监听已配对设备的连接变化，约一秒内发起设备刷新，并在稍后补读一次电量。
电量出现时间取决于 Windows 和设备上报；设备事件仅刷新蓝牙，不额外请求 AI 平台。
事件监听不可用时继续使用定时扫描。
账户指标只使用实际返回的数据，缺失项不会用估算值代替。
Codex 的账户累计 Token 与 Claude 最近会话 Token 范围不同，不等同于套餐剩余 Token。

默认配置位于 %LOCALAPPDATA%\TokenDock，升级继续沿用。
API Key 使用 Windows 当前用户范围的 DPAPI 加密保存。
从旧版本迁移时可使用 --migrate-from "旧目录\data"，已有新配置时不会覆盖。

同一次运行中的同一低位状态只提醒一次，恢复后再次降低才触发。
Windows 勿扰或通知设置可能影响提醒展示。

此版本已进行本地自动检查与本机运行验证；Win10 实机和全部设备型号仍需进一步验证。
程序仍为未签名构建，系统可能根据策略决定是否允许运行。
